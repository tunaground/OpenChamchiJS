# 본문 글꼴 선택 설계

- 작성일: 2026-11-19
- 상태: 구현됨

> **구현 중 변경 (2026-11-19)**
> - Pretendard는 가변 글꼴 판(v1.3.9, 스타일시트 53KB)을 쓴다. 일반 판은 스타일시트만 550KB다.
> - 기본값을 Pretendard로 바꿨다 (2026-11-19, 사용자 결정). 글꼴을 고른 적 없는 사용자는 Pretendard로 보이고, IBM Plex Sans KR은 후보로 남는다. 아래 본문의 "기본값 IBM Plex Sans KR"과 "기본값 사용자는 지금과 같은 요청만 보낸다"는 이 변경으로 대체된다.
> - D2Coding은 jsDelivr에 조각난 판이 없어 스타일시트 대신 전역 스타일의 `@font-face`로 선언한다 (굵기당 약 1.5MB, 쓰일 때만 받고 `font-display: swap`).

## 1. 의도

기본 글꼴(IBM Plex Sans KR)이 취향에 맞지 않는다는 사용자 요청이 있었다. 개인 설정에서 본문/UI 글꼴을 고를 수 있게 한다. 취향 문제이므로 분류(고딕/명조/고정폭/시스템)마다 느낌이 확실히 다른 후보를 둔다.

## 2. 목표 / 비목표 / 반목표

### 목표
- `/settings`의 "사이트 설정"에서 본문/UI 글꼴을 고르면 즉시 사이트 전체에 적용되고, 그 기기에 저장된다.
- 후보는 아래 9개. 기본값은 지금과 같은 IBM Plex Sans KR.

| 분류 | 후보 | 출처 |
|---|---|---|
| 고딕 | IBM Plex Sans KR (기본값) | Google Fonts |
| 고딕 | Pretendard | jsDelivr |
| 고딕 | Noto Sans KR | Google Fonts |
| 명조 | Noto Serif KR | Google Fonts |
| 명조 | 나눔명조 | Google Fonts |
| 명조 | 고운바탕 | Google Fonts |
| 고정폭 | 나눔고딕코딩 | Google Fonts |
| 고정폭 | D2Coding | jsDelivr |
| 시스템 | 시스템 기본 | 웹폰트 없음 |

### 비목표
- 고정폭 글꼴(`fontMono`: 다이스/계산 결과, 관리자 화면)과 AA 글꼴(`fontAA`)은 바꾸지 않는다. 전자는 기능용이고, 후자는 글자 폭이 바뀌면 그림이 깨진다.
- 계정 연동 없음. 기기별 저장(localStorage)이다.
- 글자 크기, 줄 간격, 사용자가 직접 입력하는 글꼴 이름은 다루지 않는다.
- 설정 화면의 별도 미리보기는 두지 않는다 (고르면 페이지 전체가 바뀐다).

### 반목표
- 설정을 건드리지 않은 사용자의 로딩이 느려지면 실패다. 기본값 사용자는 지금과 같은 요청만 보낸다.
- 새로고침할 때 기본 글꼴이 먼저 보였다가 고른 글꼴로 바뀌면 실패다.
- AA나 다이스/계산 결과의 모양이 달라지면 실패다.

## 3. 제약

- 테마는 `app/layout.tsx`의 `<head>` 인라인 스크립트가 localStorage를 읽어 첫 화면 전에 `html[data-mode]`를 설정한다. 글꼴도 같은 시점에 적용해야 한다.
- 한글 웹폰트 스타일시트는 글꼴당 100개 넘는 조각으로 나뉘어 CSS 자체가 크다. 고른 글꼴 하나만 불러온다.
- `theme.fontSans`는 `body`의 `font-family`로 쓰이고, 폼 요소는 `inherit`한다. AA 입력란도 AA 모드가 아닐 때 `inherit`하므로 본문 글꼴을 따른다 (의도된 동작).

## 4. 접근 방식

- **A. 테마와 같은 방식 (채택)**: localStorage + 인라인 스크립트로 `html[data-font]` 설정, 고른 글꼴의 스타일시트만 삽입, `fontSans`는 CSS 변수. 깜빡임이 없고 불러오는 글꼴이 하나이며 기존 구조와 같다. 글꼴 목록을 스크립트와 설정 화면이 공유해야 한다.
- **B. 스타일시트 전부 로드 후 변수만 전환**: 가장 단순하지만 8개의 큰 CSS가 모든 페이지에서 렌더링을 막는다. 반목표(기본값 사용자 로딩)에 어긋나 제외.
- **C. 쿠키 + 서버 렌더링**: 스크립트가 필요 없지만 테마와 저장 방식이 갈리고 모든 요청에 쿠키가 붙으며 페이지 캐싱에 걸림돌이 된다. 제외.

사용자가 A("테마처럼")를 골랐다.

## 5. 설계

- **글꼴 정의** (`lib/theme/fonts.ts`): 후보 목록 하나. 항목마다 키, 분류, 표시 이름, `font-family` 스택, 스타일시트 URL(시스템은 없음). 인라인 스크립트, 전역 스타일, 설정 화면이 모두 이 목록에서 만들어진다.
- **저장** (`lib/store/font.ts`): zustand `persist`, localStorage 키 `font`, 상태는 글꼴 키 하나. `lib/store/theme.ts`와 같은 모양.
- **첫 화면 전 적용** (`app/layout.tsx`): 테마 스크립트 옆에서 저장된 키를 읽어 `html[data-font]`를 설정하고, 그 글꼴의 스타일시트 `<link>`를 `<head>`에 넣는다. 저장된 값이 없거나 목록에 없는 키면 기본값으로 처리한다. 지금의 IBM Plex Sans KR 고정 `<link>`는 이 스크립트가 대신한다 (Google Sans Code 링크는 그대로).
- **전역 스타일** (`lib/theme/ThemeProvider.tsx`, `lib/theme/themes.ts`): `html[data-font="…"]`별로 `--font-sans`를 선언하고 `fontSans`는 `var(--font-sans)`가 된다. 각 스택 끝에는 지금과 같은 시스템 글꼴 대체 목록을 둔다. `fontSans`를 쓰는 기존 코드는 바뀌지 않는다.
- **설정에서 바꿀 때**: 저장소 값이 바뀌면 `data-font`를 갱신하고, 아직 없는 스타일시트면 `<link>`를 추가한다. 새로고침 없이 적용된다.
- **설정 화면** (`app/settings/settings-content.tsx`): "사이트 설정"의 테마 항목 아래에 "글꼴" 항목. 9개라 기존 세그먼트 버튼 대신 분류별로 묶은 드롭다운(`<select>` + `<optgroup>`) 하나를 쓴다.
- **번역**: `ko`/`en`/`ja`에 항목 이름, 설명, 분류 이름 4개, "시스템 기본". 글꼴 이름 자체는 번역하지 않는다.
- **문서**: `CLAUDE.md`의 Styling & Theming 글꼴 줄, `CHANGELOG.md` Unreleased.

## 6. 빌더에게 맡기는 것 (내 판단)

- Pretendard와 D2Coding의 jsDelivr 패키지/경로와 버전 고정. 가능하면 필요한 글자만 받는 다이내믹 서브셋 판을 쓴다.
- 스타일시트를 넣는 방법(렌더링을 막을지, `font-display`). 기본값 사용자의 체감이 지금과 같아야 한다.
- 글꼴마다 불러올 굵기. 지금은 300~700을 쓰며, 굵기가 적은 글꼴(나눔명조, 고운바탕, 나눔고딕코딩, D2Coding)은 있는 것만 불러온다.
- 테스트: 글꼴 목록의 키 중복 없음, 알 수 없는 키의 기본값 처리 등 순수 로직은 Jest로, 깜빡임과 실제 적용은 브라우저에서 확인한다.
